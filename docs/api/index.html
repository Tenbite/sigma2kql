sigma2kql JSON API

Every converted rule (2,461 today: 1,910 published, 551 pending), with its metadata and Defender XDR KQL, as static JSON. Free, no key, rebuilt nightly. Rules were written by the SigmaHQ community.

Machine-generated and not tested against real telemetry. Queries pass Microsoft's KQL parser against the live Defender schema, which proves they are valid KQL, not that they detect what the rule describes. Rules are under the DRL 1.1: keep each rule's author and Sigma ID if you redistribute.

Endpoints

URLWhat it is
/api/v1/index.jsonSmall manifest: when it was built, SigmaHQ commit, tool versions, counts, endpoint URLs. Check this first to see if anything changed.
/api/v1/rules.jsonAll rules with metadata and KQL (about 6.5 MB, compressed in transit).
/api/v1/schema.jsonJSON Schema for rules.json.

It is a static file, so there's no server-side filtering: download once, then filter locally. Fields are stable within v1; new fields may be added, nothing is renamed or removed without a /v2/.

Examples

curl + jq: high and critical published rules on DeviceProcessEvents

curl -s https://tenbite.github.io/sigma2kql/api/v1/rules.json | jq '.rules[]
  | select(.stage=="published" and (.level=="high" or .level=="critical") and .kql.table=="DeviceProcessEvents")
  | {title, sigma_id, query: .kql.queries[0]}'

PowerShell: rules for one ATT&CK technique

$api = Invoke-RestMethod https://tenbite.github.io/sigma2kql/api/v1/rules.json
$api.rules | Where-Object { $_.attack.techniques -contains 'T1105' } | Select-Object title, level, sigma_id

Python: rules changed in the last 30 days

import datetime, requests
data = requests.get("https://tenbite.github.io/sigma2kql/api/v1/rules.json", timeout=60).json()
since = (datetime.date.today() - datetime.timedelta(days=30)).isoformat()
for r in data["rules"]:
    if (r["modified"] or r["date"]) >= since:
        print(r["level"], r["title"], r["kql"]["file_url"])

Rule fields

FieldMeaning
uidUnique key: the Sigma ID, or pr-<number>/<Sigma ID> for pending rules.
sigma_id, title, status, level, author, date, modified, descriptionFrom the Sigma rule.
false_positives, references, tagsLists from the Sigma rule.
attack.tactics, attack.techniquesMITRE ATT&CK mapping.
stagepublished, or pending for rules from open SigmaHQ pull requests (not reviewed or merged yet).
platform, sourceWindows / Linux / macOS / Other; SigmaHQ folder (Core, Emerging threats, Threat hunting).
sigma.path, sigma.urlThe exact Sigma rule version that was converted.
kql.table, kql.tables, kql.queriesDefender XDR table(s) and the query text.
kql.file, kql.file_url, kql.raw_urlWhere the .kql file lives in the repo.
validation.statuspassed (parser + live schema) or syntax_only (too deeply nested for full analysis).
notesAutomatic fixes applied during conversion, if any.
pendingFor pending rules: pr_number, pr_title, pr_url, pr_author, change. Otherwise null.
licenseThe rule's license (DRL 1.1).

Good to know

  • Updated nightly. Pending rules come and go as pull requests open, merge, or close.
  • Be kind to GitHub Pages: fetch once a day at most, or check index.json's generated_at first.
  • Prefer git? The same data is in the repo as one .kql file per rule.
  • Found a bad rule? Open an issue.
